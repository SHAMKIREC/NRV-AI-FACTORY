# PROJECT RULES

1. Один активный проект может иметь несколько задач, но изменения не должны конфликтовать.
2. Не менять соседний проект без отдельной TASK.
3. GitHub — источник истины для TASK, REPORT и состояния.
4. Не считать UI готовым только по коду: при наличии доступного preview нужна визуальная проверка.
5. Не заменять работающий backend фиктивными данными ради красивого интерфейса.
6. Не коммитить `.env`, токены, пароли и ключи.
7. Изменения main должны быть прослеживаемы через commit/PR.
8. Если проверка невозможна, прямо указать это в REPORT.
